# GregTech-LiteHorizons

从零搭建的 Windows 离线放置工厂游戏，工程位置 **D:/GTNH_proj**。技术栈：Electron、原生 ES Modules、HTML/CSS；运行时不需要服务器或网络。

## 当前交付状态

**v0.1.5**：接入 ULV 至 MAX 的 15 级电压外观，默认随科技阶段变化，也可从「存档与设置 → 电压外观」或顶栏阶段按钮选择并固定。保留四阶段材质结构、同步阶梯／真实基地预览／STYLE DNA、MAX 浅色例外与键盘操作。系统说明见 [电压外观](docs/VOLTAGE-STYLE.md)。

免安装版与安装版保留原应用身份及存档目录。配方派工、工厂任务整理、桶与储罐、自动采集并行台数等已有功能继续保留。

## 直接运行

`release/` 提供当前 v0.1.5 的两种 EXE：

- `GregTech-LiteHorizons-0.1.5-Portable.exe`：免安装单文件，双击启动，不需要携带 `win-unpacked` 目录。
- `GregTech-LiteHorizons-0.1.5-Setup.exe`：安装版，可选择安装路径并创建快捷方式。

免安装版会自行解压到临时目录后运行；存档仍保存在应用用户目录，与安装版共用同一位置。`win-unpacked/` 是构建和验证使用的展开目录。

安装后不需要 Node.js。安装包未进行商业代码签名。

## 从源码开发

需要 Node.js 20.19+ 或 22+，建议使用当前构建环境 Node.js 24。

```powershell
cd D:/GTNH_proj
npm ci
npm start
```

也可以双击 `Start-Game.cmd`。浏览器开发预览：`npm run dev:web`，打开 `http://127.0.0.1:4173/`。

如果 `npm ci` 卡在 Electron 运行时下载，可运行 `powershell -File scripts/bootstrap.ps1`，它通过 PowerShell 下载并校验运行时；不会修改系统代理。当前电脑也可使用 `powershell -File scripts/build-windows.ps1` 复用已下载的 NSIS 资源。

```powershell
npm test                 # 模拟、科技可达性、能耗、离线一致性、存档恢复
npm run test:ui          # 浏览器导航与采集，先启动 dev:web
npm run test:desktop     # Electron 交互检查，独立临时存档
npm run pack             # 生成免安装目录
npm run dist             # 同时生成免安装单文件 EXE 和 NSIS 安装包
```

UI 检查默认使用本机 Chrome 路径；不同电脑可调整 `scripts/ui-smoke.mjs` 的 `executablePath`。

## 版本更新与 Git

工程使用本地 Git 保存源码，需求先累计修改，仅在用户明确要求更新／发布时升版本、打包，提交代码并创建 `v版本号` 标签。`release/` 只保留最新版本的 Portable、Setup、校验和、配套构建文件及展开目录，旧代码通过 Git 历史保留。

更新版本号、锁文件和界面文档后，运行 `npm run release:windows`。此命令执行逻辑测试、Windows 双目标打包、展开版及单文件 EXE 交互检查，再清理旧版 Portable／Setup、更新 SHA-256，最后提交源码并创建标签。新包验证失败时保留旧安装包；已有标签禁止覆盖。日常修改只执行相关必要检查，已检查的内容不重复运行整套 UI 测试。

构建产物、依赖、缓存、测试截图和生成的导出器 jar 不进入 Git。当前未配置远端，不自动推送。

## 新世界入门

1. 在「资源采集」连续点击树木、矿石或采集按钮。林地、地表与河岸每轮 4 次点击，完成立即掉落并入库，无需等待 2 秒。
2. 在「配方与工作台」物品列表选择「木棍」「燧石镐」，在九宫格查看原料，点「放入材料」再「合成」；机器建造同样先查看原料。
3. 在「生产工厂」给砖炉选择木炭、红砖或金属冶炼配方。
4. 红砖与燧石镐完成第一章。继续开采铜、锡、铁，制作锻造锤与金属板。
5. 用铁板部署自动采集器；用焦炉、锅炉与机器扩展生产。
6. 用 3 原木合成木桶，到「物品仓库 → 桶与储罐」放置后再到河岸收水。无可用容器时只能收集河岸的黏土和沙子，水不会散装入库。
7. 蒸汽时代合成并放置密封储罐，预留蒸汽容量后运行锅炉；蒸汽轮机从储罐取汽发电。每种流体至少需要一个兼容容器，产物空间不足时机器暂停。

机器不会擅自选择配方，也不会自动切换产品。生产中要换产品，可先点「强制停止」，再选新配方并恢复。当前电网不模拟电缆和电压等级限制。

## 存档

Windows 下 Electron 把本地存档放在应用用户目录（继续使用 `%APPDATA%/GTNH Idle/`，更名后保留此目录以兼容已有存档）的 Local Storage 中，独立于 Minecraft。当前使用 schema 3，自动迁移 v0.1.0／v0.1.1 的 schema 2 正式存档：保留物品、机器和队列，旧采集计时转成点击进度，散装流体装入独立「旧式储罐」，保持原有数量和累计产出。v0.1.2 的 schema 3 存档继续兼容，首次载入补充掉落随机状态。旧式储罐不能合成，旧流体可转入正常容器。旧临时原型存档不自动迁移。建议升级前导出存档。

九宫格使用当前放置版配方，原料数量与模拟规则一致；尚未逐项校准为 GTNH 原版工作台排布。「放入材料」用于确认本次配方，实际扣料发生在点击合成／建造时。

容器系统采用放置版规则。木桶只装水，铁桶可装水、杂酚油、原油、柴油；密封／大型储罐统一处理液体和气体，尚未实现原版温度、压力、腐蚀和等离子体材质限制。机器自动取用已放置容器，尚无实体管道要求。自动采集时容器满则不收集本轮超额流体，不会把未收集量计入产出或积攒待领取量。

代码为本工程实现。图标使用用户指定的本地 GTNH 实例中的 Minecraft 与模组自带素材（不使用额外材质包）；来源记录在 `src/assets/gtnh/sources.json`，方块投影及火箭预渲染由本工程生成。任务与语言参考同样来自该实例。
