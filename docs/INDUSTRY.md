# GTNH 2.9 工业内容对齐（累计源码，未发布）

当前采用 GTNH 2.9.0 实例中的 GregTech 5.09.54.265，导入器只读同版本 Java 源码、实例语言文件及原始模组素材，不启动或修改 Minecraft。这里是可追溯的静态子集，尚未达到“全部能源、化工和矿物流程完整复刻”。

后续科技专项、动态能源、纯净水与造物主的累计实现见 [TECHNOLOGY.md](TECHNOLOGY.md)。本文件的 4965 条为基础工业层数量，科技层另外导入，最终合并目录与依赖缺口见 `generated/catalog-audit.json`。

## 数据与来源

`scripts/import-gtnh-industry.py` 生成 `src/data/industry-import.js` 及 `industry-provenance.json`。当前包含 4965 条静态配方、47 个材料燃料声明和 68 个等离子燃料显式热值。每条配方记录源码位置；矿物模板分别记录加工模板与材料定义位置。来源清单包含安装 jar、实例配置和 Java 文件的 SHA-256。无法解析的表达式和条件记录在 unresolved 中，不用猜测值代替。

`src/data/industry-catalog.js` 将数据接入真实图鉴、派工、制作计划及设备；建造成本、采集、区域解锁与二维连接属于放置玩法改编。普通物品保留原有 ID；硫粉、盐等既有物品与相同 GT 材料共用库存。

| 范围 | 本轮接入 |
| --- | --- |
| 化工 | 化学反应、可静态解析的大型化学配方、电解、离心、搅拌、蒸馏室、蒸馏塔、加热、焦化、热解和裂化 |
| 蒸馏 | 按原版通用蒸馏方法生成整塔产物和逐馏分配方，保留编程电路号、分量、工时与 EU/t |
| 矿物 | 矿石、粉碎、洗矿、热离心、含杂／纯净粉离心、浸洗、宝石筛选和带对应标签的电磁选矿 |
| 流体 | 输入和各产物可指定实体容器或容器组；气体同样使用实际容量，不存入散装仓库 |
| 概率 | 独立产物槽按万分比掷骰；同物品的必得与概率副产物分别保留；批次掷骰结果随存档保存 |
| 制作计划 | 依赖计算只计必得产物，概率副产物不充当保证供给；概率配方可按批次安排 |
| 采集 | 新矿脉只取原版 OreMixes 中已列出的受支持区域矿物；太空矿脉保留火箭条件，不把全部注册材料开放为低压采集资源 |

主流程是矿石 → 粉碎矿石 → 洗净粉碎矿石 → 离心粉碎矿石 → 粉；也可用锻造锤／研磨机得到含杂粉或纯净粉再离心。没有把含杂粉错误套入只适用于粉碎矿石的洗矿流程。槽位按页展示，数量和概率可查看。

## 能源与统一投料

- 增加高压燃煤、熔岩、青铜太阳能及钢太阳能锅炉，按原版小锅炉类和实例 MachineStats 配置区分温度、容量、热消耗、冷却和产汽。太阳能锅炉保留普通水结垢，蒸馏水不继续结垢；本游戏采用固定 20 分钟昼夜，不模拟天气和实际空间遮挡，露天状态由设备设置。
- 固体燃料支持煤、木炭和焦煤。普通煤／木炭燃烧值 1600，焦煤 3200；焦煤值另由安装的 Railcraft 9.17.36 `FuelPlugin$FuelHandler` 字节码确认。灰烬按小锅炉规则随机产生。
- 锅炉组按钮为“全组投入 ×1 / ×16 / ×64”：只扣这一次的总量，优先给 `槽内燃料 + 未烧完热量折算` 较少的成员。运行时缺煤的成员可从组内其他槽取煤；既有存档中不均匀的存煤也能共用。燃烧仍按整块燃料启动，不把燃料或热量复制成每台一份；燃料用尽时无法保证所有锅炉继续工作。
- 同组只允许一种已装入的固体燃料。机内液体燃料或水种冲突时拒绝直接编组，避免混合后错误换算。燃料种类单独保存，停止或切换配方不会把旧存量改名为新燃料。拆除按真实煤种和水种退料。
- 柴油、燃气与半流质发电使用材料声明的热值及机型等级效率；半流质只接入原版物品单元格转换分支。等离子燃料使用源码 switch 中的 68 个显式覆盖热值；未解析质量公式生成的条目不猜测。
- 增加小型太阳能发电板与 EV–LuV 地热发电机。地热当前接入熔岩 32 EU/mB、效率 `100 − 7 × tier`、燃料罐 `5000 × tier`；不能据此声称其他热燃料已齐全。

## 存档

schema 4 仍兼容，增加 `industryRulesVersion`。被本轮替换的简化配方在制批次退还原投入，流体放入迁移储罐；schema 2 的流体继续走既有迁移流程。含失效路线的制作计划解除安排，已付料且仍有效的批次完成后停止。旧世界的存量、采集进度与本地设置不清空，不结算关闭程序后的收益。

## 明确缺口

1. 尚未取得实际运行后的完整配方注册表。附属模组、脚本删除／替换和模组条件可能改变基础 Java 生成结果；导出器保留在 `bridge/`，本轮未安装到实例或运行。
2. 科技层已补可解析的铂族/稀土/硅岩链、研究、洁净室、线圈温度、专项装配条件，但复杂 NBT、工具矿辞、容器返还、非默认密度和运行时替换仍有未解析项，材料链未全闭环。带独立加工等级的高阶金属不自动生成普通电炉捷径。
3. 大型锅炉、普通/XL 涡轮、转子寿命、大型内燃机、换热、热力锅炉、LFTR、硅岩反应堆及同位素机组已接入专项运行。IC2 核反应堆热管理、组件布置和损耗已实现；全燃料循环的材料可达性、极端状态与其他未建模特殊机组仍需补齐。
4. 科技层已扩展可解析聚变反应及 Mk I–V 的启动容量/超频；实际结构成本、全动态配方和端到端生产仍未完整验证。
5. 完整维度矿脉配置、宿主石、贫富矿、原版矿石掉落、真实多方块结构、电缆、损耗与维护尚未逐项建模。

本轮仅进行了静态语法、数据引用、图标存在性和 Git 差异检查；未运行逻辑／UI 测试、启动应用或打包。
