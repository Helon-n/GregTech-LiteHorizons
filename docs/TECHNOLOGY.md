# GTNH 2.9 科技产线移植记录

本文件描述截至 v0.1.17 的科技产线、来源修复与矿脉前置。此前永恒、星门和 17 种设备的材料来源断点已修复；目录其他分支仍有缺口，不能以配方数量或静态可达替代从新档开始的整链可玩验收。

## v0.1.17 矿脉采集前置

- 191 个导入矿脉及基础矿脉使用 `mining-reference.js` 中的 GT 原生采掘等级。依据本机 GTNH 2.9 对应 `MaterialsInit`、`MaterialBuilder`、`GTBlockOre` 及 `GregTech.cfg`；配置关闭自定义等级改写、普通矿等级上限为 7。不是匠魂经验／强化后的等级表，也未模拟不同母岩的硬度。
- 燧石、铁、青铜、钢、钻石、不锈钢、钨钢、玛玉灵、中子素、铿铀及无尽镐按能力兼容低等级矿。0 级矿仍需要镐；章节不作为采集条件。新增工具配方明确属于放置改编；不锈钢等进阶工具走装配机，中子素／无尽保留材料的加工电压，不增加后期材料手工锤制捷径。
- 矿物分布取行业／科技导入的维度并集，不再把下界、暮色森林、末地、永恒沼泽统称地表。满足任一自然分布地区即可开采；异维度需实体入口，月球／火星需火箭，其余太空目的地暂统一深空火箭，高级火箭兼容前者。42 个地区的名称与入口条件保存在目录中。尚未复刻逐级火箭、航行燃料、环境防护、地理距离或玩家位置。
- 新增下界／暮色／末地／永恒沼泽入口建造，明确作为“找到并激活入口”的放置抽象；用料不是原版传送门方块制造配方。水从实体容器扣除，建造与拆除会立即改变访问条件，不按主线章节免费授予地区。
- 小型铁／锡矿采用 `quality - 1` 的采掘门槛，互斥掉落粉碎矿或含杂粉，补充对应炉炼路线，解决初期工具前置循环。掉落类别参照 `SmallOreDrops`，次数、两类各半和炉炼的独立煤耗属于放置规则，不宣称复制原版全部随机采样／熔炉燃料机制。
- 手动采集、采集器部署、持续运行、读档后的运行、制作计划与建造来源审计共用前置判定。失去工具或入口后保留已有进度并暂停，暂停期间不累计收益；未删除旧库存或旧采集器。
- 采集卡显示地区、所需／当前采掘等级与缺失项，详细分布可悬停查看；自动采集缺条件时显示暂停原因，工作台数显示为 0。新增工具图标从原模组镐头和木柄材质描摹成 SVG，不读额外材质包。

重建依据运行 `python scripts/import-mining-reference.py`，图标运行 `python scripts/import-mining-icons.py`。本次随 v0.1.17 发布；基础与成品检查范围见 [VALIDATION.md](VALIDATION.md)。

- 灵宝分支加入付费研究笔记、源质蒸馏、注魔、奥术工作台和五级血祭坛。源质必须进入实体罐；灵宝／灵宝金属保留配方原料、源质数量和六种原始灵气各 125 的费用，血祭坛保留 50,000 LP 和 20 LP/t。研究样本、紧凑设备、灵气恢复、LP 来源和远征是明确的放置版改编，未模拟完整魔法世界。
- 深暗传送门保留压缩基岩锭、4 个 UIV 力场发生器、4 个永恒奇点、七种源质各 512 与不稳定度 32，必须先取得对应研究。补入月球奶酪矿、罪孽碎片和源质来源，接回深暗矿物、时计、永恒及后续星门材料。研究链以消耗样本的实体笔记代替研究小游戏；未模拟污染或注魔失败。
- 植物魔法保留实际魔力费用、泰拉钢三种原料和盖亚魂锭用料；工坊、花／魔力池配置及盖亚战斗采用紧凑放置版，满池不会使已点燃燃料停止燃烧。
- BEC 基础供电改为付费 UIV 64A 配置，修复强制从 UXV 开始造成的前置循环；更高电压仍需材料升级及实体供能。旧物品别名、收藏、计划和在制工单一并迁移，保留存量、剩余时间和已付电量。
- 资源与远征分页现在能访问全部采集点；无制造配方的材料显示采集来源，未满足条件的地点仍可查看并准确跳转，按钮明确显示缺少的工具／研究。

全部 16 章材料目标和全部 384 种设备的静态建造来源检查通过，不再保留原来的 2 项目标／17 台设备豁免。第二层审计同时考虑容器、研究、线圈、洁净室及部分特殊设施安装条件，但仍忽略数量、真实能源网络和升级时序；结果与运行测试范围见 [VALIDATION.md](VALIDATION.md)。

各配方保留来源位置；`industry-provenance.json`、`technology-provenance.json` 和专项 reference 记录文件哈希、未解析项及条件。

GT++ RTG 按 `MTERTGenerator` 实际代码计算：days 先取整，再乘 `20×86400×EU/t`，超过 2,147,483,647 截断，并一次加入机内储能；没有照搬 tooltip 将其错误当作 24,000 tick 的 Minecraft 日。它与 IC2 六槽永久燃料机不是同一机制。

工作台导入现在展开 `GTModHandler.addMachineCraftingRecipe` 的原版电压映射与静态九宫格图案，覆盖可解析的外壳、电路、电缆、部件和普通机器制造入口。箱子、过滤器、研磨头及分级玻璃使用原始注册表中的合法代表；这是静态代表选择，尚不等于全部矿辞替代品支持。BartWorks 分级玻璃保留 subtype、强化用料、回收配方与原始纹理。

GT++ 通用材料模板按实际 `MaterialGenerator.generate` 注册分支生成板、杆、框架、齿轮、转子、挤压、铸造、回收与可解析的固体混粉/合金高炉路线。质量、电压、辐射和熔点由材料构造推导，保留源码的平均与舍入规则。核材料的部分分解分支已经展开；未知构造、气液混合材料、核材料剩余分支及运行时额外注册仍需补充，不会用猜测配方填空。

旧放置版的异域→宇宙→超越→时空→终极电路配方已退役，后期主线改用原版光学计算机、光学主机、皮米、量子与普朗克电路。UV 目标采用湿件主机，UHV 目标采用生物处理器，光学路线需 UEV 变异活性焊料。这些电路保留实际纳米芯片加工及转换路线。旧存量和已取得记录迁移到对应电路，在制旧配方先退还原投入；存档工业规则号为 6（应用版本不变）。原版注册但未找到制造配方的占位电路物品，不因此获得虚构制造路线。Core 明确注册的 UMV／UXV／MAX 电路矿辞现已识别，并展开 GoodGenerator 的电路包循环：16 个同级电路 + 72 mB 焊锡合金，30 秒、30 EU/t、电路模式 16。

培养皿保留 BartWorks `BioLabParts:0` 的 `Name` NBT，每个菌种单独占物品身份，空培养皿不会被误当作菌种。材料别名、IC2 空流体单元、原版宝石矿辞与 GT++ 流体注册名已做同一物品身份校正；不同模组注册名仍不能因显示名称相似而合并。

v0.1.13 修复 GT++ 实体锭和流体 ID 冲突：实体采用独立 `Ingot` 身份，熔融材料采用 `Molten` 身份。迁移以 v0.1.12 不可变目录为基线，36,933 条旧科技配方全部保留或找到等价替代，1,691 条配方 ID 有迁移。旧库存和储罐存量保留；已付料批次保留剩余时间及预付电量，产物按原配方区分实体锭和流体。仅未完成的旧造物主熔融批次从错误的 1,000 mB/锭纠正为源码 144 mB/锭，已产出的罐存不倒扣；再次读档不重复转换。收藏和制作计划同步迁移。

恢复 `MetaGeneratedItem02.java:3855` 内此前漏导的机器配方：超立方体 → 8 超时空金属粉，5 秒、31,457,280 EU/t。Proto-Halkonite 热浸与真空冷却 helper 按注册的部件体积展开，保留对应原料和两种冷却流体；GT++ 显式注册的 Rhugnor 螺栓和凯芙拉板回收熔融也已接入，未向所有后期材料添加手工锤炼。

## 二维放置版改编

- 零长度逻辑端口代替空间管线；流体仍必须进入实体容器，电力缓存仍必须装实体电池。
- 深井泵建造预付 64 格管柱和结构，不模拟坐标、钻井或收管。
- 固定昼夜及手动露天状态代替天气和遮挡计算；太阳塔输出堵塞保留冷盐与热量。
- 缺水/冷却保护以停机代替破坏基地；关闭程序不产生任何离线收益。
- 手工工具要求持有但不消耗耐久，手工耗时与主线目标仍为放置版规则。章节仅用于主线参考和自动外观，不再限制配方浏览、建造、加工、采集、升级或制作计划；材料、工具、科研、能源、容器和世界条件继续生效。
- 造物主、纯净水、纳米浸液等保留专项状态；原版大规模空间结构、整网时序与极限并行尚未逐项等价。
- 纳米锻炉、纳米芯片模块与等离子锻炉捆绑独立 64A 输入，仍需实体发电机或电池箱供电。科研站捆绑按算力付费的专用计算机，不模拟机架过热和数据丢包。纳米芯片尚未复刻同一 NAC 主控的跨模块功率分配。
- `MTEPlasmaForge.createProcessingLogic` 在源码第 735 行明确调用 `setUnlimitedTierSkips()`，允许总输入功率充足时跨电压加工；放置版因此不再按普通单安机器拒绝 1,000,000,000 EU/t 的时空熔液配方。原料、40 秒、12,600 K 和完整 800,000,000,000 EU 均保留。聚敛模式额外催化剂、催化剂运行折扣和完美超频未实现；当前按未折扣原配方收费。
- 核反应堆采用固定一秒相位，EU 模式接到 EV 1A 逻辑端口；这不是原 IC2 能量网。过热保护停机代替爆炸，停机仍处理散热。流体模式必须完成实体压力容器结构并连接冷热容器，不能同时直接发 EU。
- 核组件使用后保留独立损耗状态，取出再装入不会修复。RSH/LZH 冷凝器按 Core 脚本分别消耗 8 红合金粉/8 青金石粉维修；不使用被替换的旧 IC2 配方。不同损耗的同类组件目前优先取出已有用件，尚不能逐件精确挑选。
- 培养仓按配方自动从仓库装入一份实体培养皿和兼容辐射棒，自动设定整数屏蔽比例。培养皿占用在设备中，换种或拆除时返还；已消耗的辐射棒不会因停机、换方或重开恢复。衰减按原版 `calcDecayTicks` 和质量计算，暂停期间继续衰减，关闭程序不推进。失去辐射时采用暂停保护，而非原版运行中丢弃输出的行为。
- 培养仓指定的输出容器/容器组作为逻辑输出仓，以其容量和同种流体存量计算原版抛物线培养加成，上限由源码的 1000 倍 bonus 决定，最终流体倍率至多 1001；同时受第一种进液数量限制。只等比放大首种进出液，固体原料、时间与功率不跟着倍增；付料时的倍率和产物保存到批次。每个模拟步内沿用该步选定倍率，未复刻多方块并行调度时序。空间结构与其他仓口费用仍属放置版改编。

## 静态审计与检查边界

运行 `node scripts/audit-catalog.mjs` 生成 `docs/generated/catalog-audit.json`，检查物品引用、数量、概率槽、工具格、机型电压/加工条件及来源图。

- `errors`：目录结构、引用错误，以及主线目标／设备建造来源回归。
- `unserved`：即使假设全部升级已安装，也无可用机器的配方。
- `sourceLess`：原料/工具/建造物品既没有配方产出也没有采集来源。
- `materialReachability`：从采集来源做输入/工具/研究依赖固定点，忽略数量、能源、阶段、机器建造与世界条件；不可达说明仍有缺口，可达不保证可玩。
- `constructionReachability`：增加采集工具／火箭、机器建造、实体容器、研究／培养物、线圈／洁净室及部分特殊设施条件。`milestones` 和 `unbuiltMachines` 不允许保留豁免；依旧不证明可运行的能源网络、升级材料或生产数量。
- `missingIcons`：最终目录引用的 SVG 缺失。
