# 工程实施记录

## 目标与边界

目标：将网页放置经营方向改写成 Windows 桌面游戏，以 GTNH 2.9.0 长科技线为参考，最终扩展到星门。

目前交付的是能够从新世界运行的桌面工程和简化主线。**代码可构建与原版内容完整复刻是不同验收，后一项尚未完成。**

## 本轮工业内容累计修改

详见 [INDUSTRY.md](INDUSTRY.md) 与 [TECHNOLOGY.md](TECHNOLOGY.md)：静态工业/科技导入、研究及设备条件、专项能源、八级水处理、造物主、核反应堆与热管理、酸液/火箭燃料发电、机器电压配方展开、原始工作台与 9×9 配方、概率/耗材及制作计划。v0.1.13 累计修复蒸汽阶段前置、研究及多安加工、部分后期注册遗漏和旧存档身份。仍存在后期材料闭环、核燃料整链与最终注册表缺口，测试和打包结果以 [VALIDATION.md](VALIDATION.md) 为准。

## 已实现架构

- 模拟模块不访问 DOM、文件或 Electron API。手动采集由 `Game.gather(id)` 的点击推进，自动采集、队列、机器与电网由 `Game.tick(dt)` 推进。
- 手动采集进度按资源点独立保存，时间不会推进。完成一轮按声明范围独立随机掉落一次，界面显示飘字、最近掉落和库存变化。
- NEI 风格列表按物品名显示，按产物查配方、按原料或工具查用途；R／U 快捷键、右键用途、原料点击跳转、多工艺翻页。手工和建造展示九宫格，机器配方展示工艺槽。
- 配方上方提供星标收藏；配方侧栏可在图鉴与收藏间切换，收藏项使用原有物品图标、工艺名称与分页导航，并支持搜索、取消收藏和当前项标记。收藏按具体配方去重，点击恢复收藏时的分类、物品和配方／用途上下文；未解锁项目保留但不能跳转。收藏单独保存在本机设置，重启保留，不写入世界存档；随 v0.1.10 发布，仅静态检查，未运行测试。
- 先放入材料再合成／建造。放入为确认预览，实际扣料发生在执行时；工具独立显示且不消耗。
- 原有简化配方的九宫格属于放置版设计；累计导入的静态配方保留源码形状，未知工具、容器返还与动态形状记录为未解析。9×9 配方使用终极工作台并分页显示。本轮没有运行交互或逻辑测试。
- 在线每 100 ms 更新模拟，视图约每 200 ms 局部刷新。生产 tick 不重建整页，不抢走表单焦点。
- 机器能源读数使用固定尺寸的槽位与竖向计量条：锅炉区分炉温、水输入、蒸汽输出及煤炭物品槽，数量和容量分行显示，悬停提供精确读数；设备组汇总容量并显示各炉温度范围。锅炉生产页去掉重复的配方投入／产物区，其他机器生产页采用紧凑计量条，供能／输出页显示完整槽位。刷新只更新读数、液位和无障碍属性；本项仅静态语法及差异检查，未运行测试或打包。
- 关闭程序后不结算时间，自动采集、机器生产、能源与手工队列保留保存时的进度；启动时不按 lastSeen 补算。程序运行期间的后台补帧仍使用相同规则，步长 0.5 秒。此规则已随 v0.1.9 发布。
- 固体采集数量按基础数量上下浮动，主产物至少 1 个、副产物可为 0；流体保持固定体积。每台自动采集器、每一轮独立随机，运行期间共用掉落规则，随机状态随存档保存。
- 界面正文与操作字体放大，删除原版资料页面、开发说明和重复教程，保留主线目标及必要生产状态。
- 工厂按具体机器类型分组，并可筛选；强制停止清空当前配方及批次并停机，已支付材料、电力和当前产物不返还，不影响已输出的库存与发电量。
- 每台机器运行一条玩家选定配方。能源独立模块按设备连接、内部缓冲、电压、安培、热值与效率推进，消费者不再从全局电量直接扣电。详见 ENERGY.md。
- 固体存入 inventory，流体存入 containers 或机器独立的输入／蒸汽缓冲，不允许 schema 3／4 出现仓库散装流体键。桶／储罐具有独立容量、单流体绑定与兼容范围；空容器可预留类型、转移或收起。
- 容器放置支持数量加减、全部及批量放置，数量受空容器库存和 10000 个容器总上限约束；整批校验并扣除库存后生成独立容器。放置成功保留当前容器目录及分页，便于连续放置，不自动切到已放置页。本项为累计源码修改，未运行测试或打包。
- 容器及设备支持持久化的手动命名分组，分组以统一端口参与流体输入输出和电网供给。容器同流体、设备同机型同电压，容量／产能从实体成员汇总，能源扣除继续逐台共享额度；成员管理使用图标多选与分页。实现见 `core/groups.js`、`group-editor.js` 及 ENERGY.md，本项未运行逻辑或 UI 测试。
- 液体与气体单位 mB，电量 EU，功率 EU/t，按 20 ticks/s 换算。机器启动前规划整批产物容量；并行产线抢占空间时已完成批次保留至有容量，不重复扣料或扣电。
- 焦炉及所有已解锁配方含流体产物的设备始终提供“输出”页；未选配方、暂停或同机型设备组也能预设容器／容器组。多种流体逐项分页配置，生产卡片和折叠设备提供输出入口；自动整理时将流体输出目标纳入合并条件。指定容器满时等待，不改投其他容器；固体产物仍进物品仓库。本项仅静态检查，未测试或打包。
- 河岸混合采集保留固体，容器不足的流体明确标为未收集。自动采集超额流体不计入 earned，也不积攒待领取量。机器流体副产物没有空间时整批暂停。
- 阶段目标计入累计获得或持有／部署数量，投入建造不使进度倒退。
- schema 4 存档校验并保留上一份有效备份；支持 schema 2／3 迁移。旧散装流体转入迁移罐，旧全局 EU 保留为仅能向实体电池箱转存的额度；旧批次保留剩余进度／预付能源，旧聚变输入退回迁移罐，不生成新同位素。
- 渲染器没有 Node 权限；Electron 禁止新窗口与外部导航。

## 与原版的差距

材料成形现已单独校准：解锁阶段与加工耗能分开，手工许可来自材料属性，板／杆／导线接入卷板机、车床和正确工具；依据、旧档迁移及尚未覆盖的范围见 [MATERIALS.md](MATERIALS.md)。以下规模描述为上一发布版基线，累计源码的新增内容尚未打包。

| 系统 | 当前状态 | 仍需补充 |
| --- | --- | --- |
| 配方 | 静态工业/科技、工作台与专项动态流程；最终数量见目录审计 | 最终注册表、复杂矿辞/NBT、脚本移除替换、全部容器返还 |
| 材料 | 形态、原始注册物品、元数据及材料依赖审计 | 消除无来源材料/依赖环、完整素材与本地化 |
| 机器 | 多种普通/专项加工与能源机型，独立缓存、研究/线圈/结构等级条件 | 全部真实建造费用、原版维护和空间结构 |
| 能源 | 指定直连／缓存供能、实体电池、输出安培、电压限制、普通超频；已校准氘氚聚变的启动与超频 | 实体电缆／损耗／变压器／爆炸、特殊多方块、完整燃料化工链和全部发电机型 |

## 后续实施顺序

1. 取得实例运行时配方快照，补工作台、熔炉与特殊注册表。
2. 优先逐条校准石器→蒸汽→LV 的输入、输出、工时、工具和能耗。
3. 实现机器缓存、管线端口、过滤与堵塞行为。
4. 扩展 MV→EV 原版登月；处理高炉温度、真空、洁净室和燃料路线。
5. 按章节补 IV→MAX，分别校验生产可达性和工艺条件。
6. 补独立支线后进行数值平衡、整链生产回归和视觉完善。

需要改变用户游戏状态的工作（安装导出器并等待实例加载）没有在后台执行。
